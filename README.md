# دليل العشاء المنزلي الذكي

[![CI](https://github.com/AQBassam/SmartDinner/actions/workflows/ci.yml/badge.svg)](https://github.com/AQBassam/SmartDinner/actions/workflows/ci.yml)

يعمل على **https://dinner.bassamailab.xyz** · النشر: [`deploy/DEPLOY.md`](deploy/DEPLOY.md) · ملف التسليم: [`HANDOVER.md`](HANDOVER.md)

المخرج العملي لسؤال «وش نسوي عشا الليلة؟»: تبويب **اليوم** يحسم وجبة الليلة بعد الغداء، ويحسب موعد بدء الطهي من موعد العشاء، ويوزع التجهيز المسبق على لحظات موجودة أصلًا في يوم الأسرة (يوم التسوق، ومساء تجهيز غداء الغد، وبعد الغداء).

تطبيق ويب (PWA) ثابت بلا خادم: خطة عشاء من 18 وصفة (R01–R15 من النسخة الثانية + R16–R18)، قائمة تسوق **تتولد من الوصفات**، فئات عمرية وشهية، حساسية ومكونات مستبعدة، مخزون جزئي، أسعار لولو ونستو وهايبرماكس مع مقارنة، وتذكيرات لتقويم الهاتف: التسوق، وعشاء الليلة 4:15، ومهام الليلة 9:30.

## التشغيل

```bash
npm ci
npm test                 # 50 اختبار وحدة: البيانات، المولّد، الجدول اليومي، الطوارئ، الأسعار، الترحيل، التصدير
npm run dev              # تطوير محلي
npm run build            # dist/  → النشر على dinner.bassamailab.xyz
npm run build:preview    # dist-preview/index.html → ملف واحد للمعاينة (دون Service Worker)
npm run release          # اختبار + بناء + release/dinner-release-<version>.tar.gz مع SHA256SUMS وسكربتات النشر
npx tsx scripts/report.ts 5          # تقرير تدقيق: كل الدفعات والكميات والتكلفة لخمسة أفراد
python3 scripts/images.py photos/    # صور الوصفات: photos/<id>.jpg + credits.json ← public/recipes/*.webp + src/data/images.json (انظر docs/Recipe_Photo_Brief.md)
python3 tests/e2e.py dist shots/     # 32 اختبار متصفح تحت سياسة CSP الإنتاجية (بساعة مثبتة)
```

## البنية

| المسار | الدور |
|---|---|
| `src/data/catalog.json` | كتالوج المكونات: الوحدة، التحجيم، أيام الحفظ، التجميد، العبوة، السعر ومصدره، مسببات الحساسية |
| `src/data/recipes.json` | الوصفات R01–R18، الكميات لخمس حصص، الأدوات، الخطوات مع مؤقتات، مهام التجهيز المسبق (`prep`: shopDay / evening / afternoon بالدقائق)، الترتيب الافتراضي |
| `src/lib/engine.ts` | المولّد: احتياجات كل ليلة → توزيع على الدفعات حسب الصلاحية → تقريب العبوات مع إعادة استخدام الفائض → الميزانية والتذكيرات |
| `src/lib/schedule.ts` | الجدول اليومي: مهام يوم التسوق، ومهام الليلة لعشاء الغد (إذابة + تجهيز)، ومهام بعد الغداء، وموعد بدء الطهي، وأحداث التقويم، وتبديل الطوارئ |
| `src/lib/prices.ts` | سجل الأسعار لكل متجر، اختيار السعر حسب الوضع، الصلاحية والقِدم |
| `src/lib/state.ts` | مخطط الحالة v3 (zod)، الفئات العمرية، التحميل الآمن، الاستيراد المحصّن |
| `src/lib/migrate.ts` | ترحيل الإصدار الأول، وملف HTML الثاني، ونسخة React السابقة، مع جداول تحويل المعرّفات |
| `src/lib/ics.ts` | ملف تقويم RFC 5545 مع تنبيهات |
| `src/components/*` | الواجهة: اليوم، الخطة، التسوق، الوصفات + وضع المطبخ، المزيد (والميزانية من التسوق والمزيد) |
| `deploy/` | install / rollback / verify، وإعداد nginx للنطاق الفرعي مع CSP والتخزين المؤقت |

## إضافة وصفة

1. أضف أي مكوّن جديد إلى `catalog.json` (مع `sold` و`price` و`source`).
2. أضف الوصفة إلى `recipes.json` بكميات لخمسة أفراد ومهام `prep` (مهمة واحدة على الأقل)، وأضف معرفها إلى `defaultOrder` إن أردت.
3. `npm test`: اختبار سلامة البيانات يرفض أي مكوّن مجهول أو كمية ناقصة أو سعر "موثّق" دون تاريخ ورابط.

## مصادر الأسعار

- `verified`: تحقق مباشر من صفحة المنتج في لولو عُمان الإلكتروني بتاريخ 2026-10-18 (9 أصناف).
- `recorded`: مسجل في الإصدار الأول، لم يُعَد التحقق منه (الزبادي، الموزاريلا).
- `estimate`: تقدير تخطيطي. يستطيع المستخدم إدخال سعره ويُحفظ بتاريخه.
